# M158: glmmTMB fits retry a variance stuck at zero, and a zero-width interval is refused

- **Status:** review
- **Priority:** high
- **Depends on:** —
- **Driving RR:** —
- **Principles touched:** IP1, GP1, GP7, GP9
- **Resolves:** —
- **Surface tier:** user-facing — it changes what `icc()` returns or refuses on the default engine
- **Branch/PR:** m158-glmmtmb-false-zero

## Goal

A default-engine fit that stops with a variance near zero is refit once from a second start. On the planted grid the second fit reaches the REML optimum. On a glmmTMB fit under `ci_method = "montecarlo"` or `"bootstrap"`, `icc()` refuses an interval whose two limits are exactly equal. The Monte-Carlo overflow abort no longer tells a glmmTMB user to refit with glmmTMB.

## Scope

**In:** A second-start refit in the shared glmmTMB fit path (`fit_glmmtmb_ml_model()` in `R/engine-glmmtmb.R`). It fires when the fit leaves a random-effect or residual SD near zero. The second fit is kept only when its REML objective is lower by more than 1e-6. The review pass 1 fixes to it: the 1e-6 margin and its comment, the warnings of a first fit that then errors, and non-finite fixed effects in the second start. A classed refusal (`intraclass_zero_width_interval`, also `intraclass_singular_fit`) of an interval whose limits are finite and equal. It applies to glmmTMB fits under `ci_method = "montecarlo"` or `"bootstrap"`. A rewrite under GP9 of the degenerate-data test in `tests/testthat/test-boundary-abort-hint.R`, which is red on `main` since `9ea6d9a`. The Monte-Carlo overflow abort's hint, which tells a glmmTMB user to refit with `engine = "glmmTMB"`. An `mc_interval()` engine argument that takes the engine object, as its siblings do, with its `mc_ci()` and `d_study()` callers. D-048, which supersedes D-004's glmmTMB and Monte-Carlo and Bootstrap cells. One new decision entry that supersedes D-048's width bound and kept-fit rule. The matching `DESIGN.md § Boundary-fit policy` rows, and one NEWS bullet.

**Out:** A false zero whose interval has a nonzero width, however small. The second start handles those. At review return 1 the user chose not to refuse them, because no width bound tells a false zero from real near-perfect agreement. A note on this in `?icc`, which the re-cut question set declined (NEWS only). The second start inside bootstrap refits (`glmmtmb_simulate_refit()`). Under D-004 a refit at the boundary stays a kept draw. An automatic cross-check against the lme4 engine, close to the fallback that D-026 refused. A user report of a false zero that the second start does not fix brings it back as a question. The student's reported data, which the user chose not to re-run. The other engines: lme4 and lavaan share `mc_ci()` and `bootstrap_ci()`, but the refusal is gated to glmmTMB fits. The other `ci_method` values, which compute their own intervals. The four review follow-ups and the unclassed glmmTMB errors on data with no variation within subjects, which are candidate rows.

## Acceptance criteria

- [x] AC1: On a planted false optimum, the default engine reaches the REML optimum. `tests/testthat/test-glmmtmb-false-zero.R` masks `glmmtmb_start()` to return `NULL`, which restores glmmTMB's own start (the behavior before PR #176). It uses the 17-subject, 2-rater frame of `scale_two_way()` with the scores multiplied by 1000, for seeds 1 to 40. It fits three models: `raters = "fixed"` with `type = "agreement"`, random raters, and `model = "oneway"`. Take every seed and model where the lme4 engine reports the first ICC above 0.01. Each of the three models has at least one such seed. There the glmmTMB fit reports that ICC within an absolute 1e-4 of the lme4 engine, or within an absolute 1e-3 where the REML objectives of the two engines' fits agree within 1e-6. It also reports that ICC within an absolute 1e-5 of the glmmTMB fit on the unscaled scores. On each of the three models, at least one seed has lme4 above 0.01 and a glmmTMB first ICC below 1e-6 when the second start is also disabled.
- [x] AC2: The second start never makes a fit worse. For every fit in AC1's grid, the REML objective of the fit that `fit_glmmtmb_ml_model()` keeps is at most the objective of the first fit. The grid includes at least one fit where the second fit is kept. The second fit is kept only in two cases: both objectives are finite and the second is lower by more than 1e-6, or the first is not finite and the second is. If the second fit raises an error, the first fit is kept. If the first fit has a non-finite fixed effect, the second start holds only finite values. If the first fit signals a warning and then an error, the call signals that warning before the error. Tests in `tests/testthat/test-glmmtmb-false-zero.R` assert each of these, with planted objectives on both sides of the 1e-6 margin and a non-finite one.
- [x] AC3: Exactly equal limits are refused on glmmTMB fits only. Take a glmmTMB fit under `ci_method = "montecarlo"` or `"bootstrap"`. If both limits of any reported estimand are finite and equal, `icc()` aborts and returns no result. The condition has class `intraclass_zero_width_interval` and also class `intraclass_singular_fit`. Tests call `mc_ci()` and `bootstrap_ci()` directly (GP9). Each fires the guard with one estimand whose limits are equal beside one wide estimand. Each shows that the same equal limits on a non-glmmTMB fit (lme4 as the probe) are not refused. Each also shows that a glmmTMB interval of width 1e-10 is not refused. Take a 20-subject, 3-rater frame with subject SD 1 and rater-error SD 1e-5 (`set.seed(1)`). Through `icc()`, neither method raises `intraclass_zero_width_interval` on it.
