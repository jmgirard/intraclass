# M168: The engine re-raise passes converted warnings and stack overflows unchanged

**Status:** done (2026-10-19, PR #187 https://github.com/jmgirard/intraclass/pull/187)

**Goal:** On the glmmTMB and lme4 engines, `icc()` stops labeling as a singular fit the engine errors that R itself marks as something else, and its error messages say only what the package knows.

**Outcome:** `reraise_engine_error()` (`R/abort.R`) records each warning it sees at `options(warn = 2)` or above. An error that `is_converted_warning()` matches passes unchanged: same call as the recorded warning, and a message identical to R's translated `gettext("(converted from warning) %s", domain = "R")` applied to it. An error inheriting `stackOverflowError` also passes. Every other non-rlang engine error is re-raised as before; a conversion that R cut at `getOption("warning.length")` bytes no longer matches and is re-raised. The re-raised message now opens "The <engine> engine stopped with an error." with "One possible cause is a variance component that the data cannot identify." The equal-limits bullet of `refuse_zero_width()` is now "Inspect the data and the fitted variances." (its example was data D-052 refuses before any fit), which also reaches the `d_study()` band refusal. `?icc` (`score`), the development NEWS bullet and DESIGN.md's Classed-deferral line and Boundary-fit rows describe it.
