# M147: `choose_icc()` answers the type question with "both"

**Status:** done (2026-08-28, PR #158 https://github.com/jmgirard/intraclass/pull/158)

**Goal:** Let `choose_icc()`'s `type` axis take `"both"`, the value its own `unit` and `level` axes already take, so a user who wants the agreement/consistency pair gets a recommendation for the pair instead of being made to choose one.

**Outcome:** `validate_choice()` accepts `"both"` for `type` (`R/choose-icc.R:318-323`) and `recommendation_rows()` gained a `types` loop mirroring its `units`/`levels` switches, type outermost — the order `icc()` builds its estimate table in — so `type = "both"` returns one row per (type x level x unit): two rows on the plain two-way case, eight crossed with `unit = "both"` and `level = "both"`, each label still read from `icc_estimand()`. `build_icc_call()` omits `type =` when both are wanted, the shape `unit` and `level` already used, and its M44-era comment claiming `choose_icc()` "resolves to ONE coefficient" — false since `unit = "both"` shipped — is corrected. `recommendation_rationale()` and `recommendation_notes()` gained their both-type sentences (the note says the omission is deliberate); `format.icc_recommendation()` expands `"both"` before `icc_design_phrase()`, whose vector argument would otherwise take an unrecognised string, so the header reads "two-way random, absolute agreement & consistency" exactly as a fit reporting both prints. The interactive walkthrough offers a third `type` choice. Swept: `@param type`, `man/choose_icc.Rd`, both vignettes, `README.Rmd`/`.md` and `NEWS.md` — five of which claimed a single recommended coefficient and now read "the coefficient or coefficients".

**Decisions:** none promoted. Milestone-local: AC1 was amended at a mini gate mid-implementation — its named case paired `ICC(C,1)` with Shrout & Fleiss `ICC(3,1)` under random raters, but that is the *fixed*-rater label and `test-choose-icc.R:122` has asserted the `NA` since M12, so the criterion was unsatisfiable as written; the maintainer corrected the labels rather than switch the example to fixed raters. Row order (type outermost) was settled in-session without a gate.
