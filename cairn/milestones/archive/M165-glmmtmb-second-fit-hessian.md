# M165: The glmmTMB second start never trades a positive-definite fit for one that is not, and passes on only the kept fit's conditions

**Status:** done (2026-10-19, PR #184 https://github.com/jmgirard/intraclass/pull/184)

**Goal:** `fit_glmmtmb_ml_model()` reports what the kept fit says: a second fit whose Hessian is not positive definite never replaces a first fit whose Hessian is, and only the kept fit's warnings and messages reach the user.

**Outcome:** `glmmtmb_second_wins(first, second)` (`R/engine-glmmtmb.R`) reads both fits. With both REML objectives finite, the second fit is kept only when it is lower by more than `glmmtmb_keep_tol` and its `sdr$pdHess` is TRUE or the first fit's is not (`NA` and `NULL` count as not TRUE); with only the second finite it is kept as before. `glmmtmb_capture()` holds warnings and messages in signal order, `glmmtmb_replay()` passes on the kept fit's through `cli_warn()` and `cli_inform()` with the text as a value, and `glmmtmb_replay_failed()` replays a failed first fit's messages, and its warnings only when `getOption("warn") < 2`, so under warn >= 2 the fit's own error reaches `icc()` as `intraclass_singular_fit`. `glmmtmb_warn()` is gone. Test helper `scale_two_way()` draws under `with_rng_seed()` through `scale_two_way_draw()`. Tests: the kept-fit table and a real-first-fit pair in `test-glmmtmb-false-zero.R`, new `test-glmmtmb-fit-conditions.R` (both directions, braces, warn 0 to 3), and an RNG-state test in `test-glmmtmb-start-scale.R`. NEWS second-start entry and the DESIGN.md glmmTMB policy row state the Hessian condition.

**Decisions:** D-057 (plan commit): the Hessian condition on the kept-fit rule, superseding D-049's rule in part. D-057 Amendment 1: the Monte-Carlo interval does not read `pdHess`; a non-positive-definite Hessian usually gives a finite, indefinite covariance whose draws overflow, so the interval aborts later. Warn >= 2 handling and message holding were milestone-local plan choices.
