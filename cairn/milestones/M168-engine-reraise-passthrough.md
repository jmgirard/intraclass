## Goal

On the glmmTMB and lme4 engines, `icc()` stops labeling as a singular fit the engine errors that R itself marks as something else, and its error messages say only what the package knows.

## Scope

**In:** `reraise_engine_error()` (`R/abort.R:216`) passes two kinds of error unchanged. The first is an error that R converts from a warning under `options(warn = 2)` or above. The second is an error of R's class `stackOverflowError`. Neither check reads message text from an engine (D-022's reason). The first line of the re-raised message changes from "The <engine> engine failed on these data." to "The <engine> engine stopped with an error." A variance component that the data cannot identify stays in the message as one possible cause. The equal-limits refusal of `refuse_zero_width()` (`R/ci-montecarlo.R:195`) drops its clause "for example for scores that do not vary within subjects". D-052 refuses such data before any fit, so the clause names data that cannot reach this message. Since M166, the band refusal of `d_study()` shows the same bullet. The milestone also edits `?icc` (`score`), the development NEWS bullet on the re-raise, and the DESIGN.md Classed-deferral line. D-059 supersedes D-053's re-raise rule in part.

**Out:** An allocation failure and a bug in package code stay re-raised as `intraclass_singular_fit`. R gives both a plain `simpleError`, so only message text can tell them apart (D-053 Consequences). This milestone graduates the row "M162 review follow-ups on the engine re-raise". The lavaan and brms engines stay outside the re-raise (row "two-way data with zero residual"). Real-data cases of the equal-limits refusal stay with the row "Equal-limits refusal unseen on real fits".

## Acceptance criteria

- [x] AC1: Under `options(warn = 2)`, a warning planted at either of two sites reaches the caller of `icc()` as R's own converted error, not as `intraclass_singular_fit`. The two sites are the glmmTMB fit, whose held warnings are replayed through cli, and `lme4::lmer()` inside `fit_lme4()`, whose warning handler passes them on through cli. A test in `tests/testthat/test-zero-residual.R` plants one warning at each site, with no braces in its text. At `warn = 2`, it asserts that the class of the caller's error is `c("simpleError", "error", "condition")`, that its message starts with `gettext("(converted from warning) ", domain = "R")`, and that it contains the planted text. At `warn = 0`, on data where no SD falls below `glmmtmb_zero_sd`, the same call returns a result and signals exactly one warning whose message contains the planted text.
- [x] AC2: An error that inherits R's class `stackOverflowError` and reaches the glmmTMB or lme4 engine dispatch of `icc()` reaches the caller as the same condition object, not as `intraclass_singular_fit`. An error that an engine function catches itself, such as in the glmmTMB second start, is out of scope. On each engine, a stub engine function signals a condition of class `c("expressionStackOverflowError", "stackOverflowError", "error", "condition")`, and a second stub one of class `c("CStackOverflowError", "stackOverflowError", "error", "condition")`. The test asserts that the caller's condition is `identical()` to the planted one.
- [x] AC3: An engine error that is not an rlang error, does not inherit `stackOverflowError`, and is not R's conversion of a warning is still re-raised as `intraclass_singular_fit`, with that error as its parent. Tests show this on each engine at `warn = 0` and at `warn = 2` with no warning before the error. A further test runs at `warn = 2` with a warning that a handler around `icc()` muffles, followed by a stub engine error with a `NULL` call, and that error is still re-raised. The re-raise and pass-through tests in `test-zero-residual.R` and the warn tests in `test-glmmtmb-fit-conditions.R` pass. What they assert does not change, except the first-line text that AC4 replaces.
- [x] AC4: Rendered with `cli::format_message()`, the first line of the re-raised message reads "The glmmTMB engine stopped with an error." or "The lme4 engine stopped with an error.". A later bullet names a variance component that the data cannot identify as one possible cause. The existing re-raise test of `test-zero-residual.R` asserts both.
- [x] AC5: Rendered with `cli::format_message()`, the equal-limits refusal on a glmmTMB or lme4 fit no longer contains "do not vary within subjects". It still contains "Inspect the data and the fitted variances". Tests assert both for the refusal raised by `icc()` (`test-glmmtmb-false-zero.R`) and by `d_study()` (`test-dstudy-band-checks.R`).
- [x] AC6: `?icc` (the `score` argument) and the development NEWS bullet on the re-raise say that two kinds of error pass unchanged: an error that R converts from a warning under `options(warn = 2)`, and an error of class `stackOverflowError`. They also say that other engine errors that are not rlang errors are still re-raised. An AC1, AC2 or AC3 test asserts each of these claims.
- [ ] AC7: `devtools::test()` reports 0 failures and 0 warnings. The raw Status line of `devtools::check()` reads OK, or each NOTE has a stated reason. `devtools::document()` leaves no diff. `air format --check .` and `lintr::lint_package()` are clean. Each `data-raw/check-*` script exits 0 on the repo.
