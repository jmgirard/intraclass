## Candidates

- MPL κ_m **monotone envelope / smoother** over the shipped table's S dips — the calibrated κ_m is non-monotone in S at every level (worst downward step −0.046 at 0.90, −0.068 at the shipped 0.95, −0.162 at 0.99: MC noise, bootstrap SE ≈0.03–0.04), so linear-in-S interpolation is not conservatively biased as `R/ci-mpl.R` once claimed. A running-max envelope (only ever widens) or a monotone smoother would remove the dips — **chosen against at the M91 plan gate (2026-07-24)** for traceability: the shipped numbers would no longer be the ones M90's coverage sweep measured. **The first probe has now run and found no cost:** M91's three off-node cells (D1–D3, incl. R=2 at 0.99 across the −0.154 dip) all clear their frozen floors, so promote only on evidence a dip costs coverage at some *other* geometry. **M92's three 0.95 off-node cells** each cleared the frozen 0.93 floor under the shipped linear rule — including one across 0.95's worst dip and one where the chord sits below a concave curve on a large-κ_m bracket — so its pre-registered bracket-max consequence did not fire and the lookup is unchanged. Promote on a cell that falls below its floor, not on the non-monotonicity itself; per-cell figures are in § M92 of `cairn/references/mpl-twoway-random-comparison.md`. Lineage: M88 table → M90 tables → M91 plan gate → M91 T2 → M92 T7.
- Restore **high-side (`pmin(1, .)`) clamp detection** in the AC4 endpoint-parity test (`test-boundary-abort-hint.R`, "verification inspects exactly the endpoints icc() reports"). The row this replaces claimed the 2026-08-01 pole hotfix removed the test's anti-clamp coverage outright; **measurement at the M98 plan gate (2026-08-01) falsified that** — low-side detection survived, so `pmax(-1, .)` and `pmax(0, .)` still red: the finite-below-−1 class via the M97 npbootstrap `unit = "average"` cell (−2.5338 at `seed = 4`, its sole supplier), and the `pmax(0, .)` class via eight boundary cells. M98 asserts those per class and adds the uncovered non-finite class. The **high side** is what was genuinely lost: no shipped `ci_method` can report an endpoint above +1 since `npb_guard_sb_pole()`, so a probe needs a synthetic reducer or an endpoint injected into a direct reducer call — **rejected at the M98 plan gate** because neither exercises the reporting path the test exists to pin. Promote on a shipped path that can again report above +1, or on a probe design that keeps the reporting path in the loop. Lineage: M93 AC4 → hotfix `hotfix-searle-pole-out-of-support` (PR #105) → M98.
- MPL interval **conflates a boundary limit with a root-finding failure** — `R/ci-mpl.R:178-188` (SHIPPED) and its offline twin `data-raw/m86-mpl-lib.R:148-155` both return endpoint `0`/`1` from `tryCatch(stats::uniroot(...), error = ...)`, so a non-finite deviance is indistinguishable from a confidence limit that genuinely sits at the boundary, and the metric that would expose it is saturated (`p_lower0` runs 0.944–0.9995 at the near-zero-ρ cells C2/C3/C7/C8/D4). Low severity by construction: `f(rho_hat) = -crit < 0` always, so `uniroot` errors precisely when the deviance never crosses the critical value on that side — the boundary answer is the correct one in the dominant case. Fix is to test the sign condition explicitly and reserve an abort for a genuine failure, which changes shipped user-facing behavior and so needs its own assessment rather than riding on the offline-generator fix; **declined for M96 at the plan gate (2026-07-25)** for that reason. Promote via `/milestone-plan`. Lineage: M86 lib → M88 port → M95/M96 plan gate.
