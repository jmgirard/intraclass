## Candidates

- **The checkpoint routing check's known blind spots** — M120 descoped these at its fourth review rather than attempt a fifth universal reachability rule; all three are recorded in `data-raw/checkpoint-sites.tsv` and promised by no criterion. (a) The walk parks a call only under `if`, so a guard call reached through `while (FALSE)`, `for (i in seq_len(0))`, `repeat { break }`, `switch`, a list-held function, `local({})` or `quote()` counts as reached — eight such forms were verified to pass at return 4. (b) A bare `readRDS` inside an `mclapply` worker aborts and is reported, demonstrated in `m120-checkpoint-guard-demo.R`, but AC3 no longer promises it, the internal-tier standard barring a promise that rests on a demonstration spanning process boundaries. (c) The `api`, `#@appliers` and `#@idioms` declarations have no floor — blanking a site's `api` cell makes its per-call mutations vacuous, and either list can be widened in the TSV alone. Promote on a declared site needing one of these shapes, or on a reversion reaching a fixture through one — never on the count of shapes. Lineage: M120 return 4 → the return-4 descope (2026-08-15).
- ~~**A resume cache can reprint identity evidence it did not recompute**~~ — **promoted to M122** (2026-08-16), with this row's own fix shape superseded and its second half falsified. Original F6: M121's `cell_spec()` pins the cell's design parameters and a hash of the generating block, but nothing about the *content* of the input fixture it verifies against (`data-raw/m111-fallback-results.rds`), so editing a recorded endpoint, keeping the checkpoints and re-running resumes all 64 cells against a fixture nothing was compared to. This row proposed adding a fixture digest to the spec; **the plan gate chose removal instead** — hardening would have been the second pass over M120's machinery, so M122 deletes the resume cache from that one site and the staleness question with it. Two audit findings against the digest shape stand recorded for any future site that wants one: `ckpt_spec_mismatch()` compares parameters with `isTRUE(all.equal(...))` (`data-raw/checkpoint-guard.R:297`), so a digest held as a numeric vector is compared at 1.5e-8 relative tolerance and would not fire on the 1e-9 edit it exists to catch — it must be a character scalar; and `check-checkpoint-sites.R` rule 5 requires a new parameter to be declared in `checkpoint-sites.tsv` in position, as a literal named argument. **F7 is falsified, not deferred** (corrected M122, 2026-08-16): it held that a `cell_rows()` reporting an assumed count rather than a counted one would still pass, but no reachable input distinguishes the two — `one_rep()` contributes exactly 2 per rep or aborts (`data-raw/m121-npbootstrap-skew-sweep.R:390-435`) — so the proposed real-cell probe would pass equally under the defect, and the hand-built cases it would have replaced cover an assertion branch (`n_endpoints` short) a real truncated cell cannot express. Lineage: M121 review F6/F7 → M122 plan gate.
- **Deserialization forms the checkpoint watcher never sees** — the run-time watcher traces `readRDS` only, verified at the M120 re-cut audit by running them: `load()` and `unserialize(readBin(...))` of a registered checkpoint both return silently and are absent from the end-of-run assertion, as is any `readRDS` given a connection. M120 fences this rather than closing it: its AC2 plants a call to each name in a declared list (`readRDS`, `load`, `unserialize`, `readr::read_rds`) in each declared site and requires the static check to report it, so a site ADOPTING one of those forms reds, while the watcher still cannot observe one at run time. Promote on a declared site needing to read its checkpoint by any form the watcher does not trace — that is the falsifier, not a count of forms — or on a sixth harness arriving that resumes through one. Lineage: M120 re-cut criteria audit round 2.

- ~~**Measure Burch's leptokurtic width reversal on a both-components-non-normal grid**~~ — **promoted to M118** (2026-08-13), with the doc reconciliation it forces split off as M119. The plan gate narrowed the grid to Burch's six *symmetric* Table 2 families: his reversal claim is about symmetric leptokurtic data, and the five asymmetric families were dropped outright rather than deferred (no published figure would check a skewed finding). Original row: Burch (2011) §4 reports the REML interval running *wider* than the exact-F one for symmetric leptokurtic data ("thus wider intervals are warranted"), drawing both `A_i` and `e_ij` from the studied distribution. M116 bounds its doc claim to what these grids measured rather than running this. Promote on a need to advise users about interval width under heavy tails, or on a report of `burch` running wider in practice. Lineage: M115 re-review G1 → M116 plan gate.
